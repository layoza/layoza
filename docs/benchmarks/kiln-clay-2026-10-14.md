# Benchmark write-up: Kiln & Clay (2026-10-14)

> Do not load this file into an agent that is building this brief; it contains the competitors' design solutions.

Brief: ``examples/benchmark-kiln-clay/BRIEF.md`` (archived artifact unavailable),
a small-batch ceramics studio in Lahore selling tableware online and running
weekend wheel workshops. Same model, five builds run in isolation: no skill,
ui-ux-pro-max, impeccable, Layoza v1, Layoza v2. Results table: `README.md`.

## 1. The craft-brand reflex is real and measurable

The no-skill control and ui-ux-pro-max produced the **same** page: cream
ground, terracotta accent, italic display serif, decorative initials at ~1:1
contrast. Layoza v1 went generic-agency (Syne, bone/terracotta). That is what
"category default" looks like in practice. If your palette draft for a craft,
food, wellness, or local-maker brief contains cream + terracotta + an italic
serif, you are in the rut: go back to the seven candidates.

## 2. Winners derived the world from the place

The two strongest identities (impeccable; Layoza v2 close behind) both mined
**Lahore kashi kari tilework** and **Multani blue pottery**: cobalt,
turquoise, ochre/haldi, white slip, a geometric tile repeat. Product names and
glaze notes came from the city (Shalimar bowl, Ravi plate, Anarkali cups,
"Multani cobalt over white slip", "Ravi-silt clay"). `distinctiveness.place_cues`
exists to make this the default path, not a lucky one.

## 3. Put the real action in the hero

The page judged best showed one real product in the first viewport, with
name, glaze note, price, and a working **Add to cart** that updated the cart
count, alongside "Shop this firing" and "Book a wheel class". Layoza v2's hero
had strong world-building (batch number, firing date, an animated wheel) but
only links to the shop. For stores, the hero holds a purchasable thing; for
bookings, an open slot; for SaaS, the product doing its job.

```html
<article class="hero-piece" aria-labelledby="hp-name">
  <svg class="hero-piece__art" role="img" aria-label="Cobalt-on-white bowl"><!-- authored SVG --></svg>
  <p class="hero-piece__batch">Out of Friday's kiln</p>
  <h2 id="hp-name">Shalimar Bowl</h2>
  <p>Multani cobalt over white slip</p>
  <p class="price"><data value="2800">PKR 2,800</data></p>
  <button type="button" class="btn-primary" data-add-to-cart="shalimar-bowl">Add to cart</button>
</article>
```

## 4. CLS from font swap: metric-adjusted fallback

The no-skill control failed CLS (0.136); the impeccable build had the lowest
(0.010). Web fonts swapping in over a default fallback move every line. Declare
a local fallback whose metrics match the web font and put it second in the stack:

```css
@font-face {
  font-family: "Display Fallback";
  src: local("Arial Bold"), local("Arial-BoldMT"), local("Arial");
  font-weight: 600 800;
  size-adjust: 91%;          /* tune per face: match x-height/advance width */
  ascent-override: 100%;
  descent-override: 26%;
  line-gap-override: 0%;
}
@font-face {
  font-family: "Body Fallback";
  src: local("Arial");
  size-adjust: 98%;
  ascent-override: 96%;
  descent-override: 26%;
  line-gap-override: 0%;
}
:root {
  --font-display: "Your Display Face", "Display Fallback", sans-serif;
  --font-body: "Your Body Face", "Body Fallback", sans-serif;
}
```

Take the override values from the font's own metrics (or a tool such as
Fontaine/Capsize) rather than guessing; then confirm with `layoza qa` that CLS
≤ 0.1. Preload only the one face the LCP element uses.

## 5. Sticky headers need `scroll-padding-top`

Layoza v2's only QA error was keyboard focus landing under the sticky header
(WCAG 2.2 SC 2.4.11, `focus-obscured`). One line fixes it:

```css
:root { --header-h: 4.5rem; }
html { scroll-padding-top: calc(var(--header-h) + 1rem); }
```

If the header height changes at breakpoints, update `--header-h` in the same
media query. Re-run `layoza qa`; the check tabs through focusable elements.

## 6. Read both checkers, game neither

impeccable's detector encodes impeccable's taste (it favoured impeccable's own
page); `layoza qa` encodes measurable defects. Use the detector's findings as
taste prompts, the QA errors as hard gates, and never tune a page to a
checker's blind spot.
