# Author the section, not a preset

For rich-motion briefs, one coherent motion thesis can support several substantial chapter transformations. It does not mean one animated hero followed by repeated entrances. Keep reading and proof sections quiet when motion adds no meaning.

Start with the actual object and visitor job. Write `motion_plan` for `recommend_animation`: thesis plus sections with id, role, object, visitor_job, family, transformation, resolved_state and phone. Candidate families are ingredients; a label such as "material assembly" is not a designed scene. Specify what separates, travels, connects or resolves, and where the reader looks.

Examples of reasoning, not a site template:

| Content | Earned movement | Weak substitute |
| --- | --- | --- |
| An interconnected service | Actual interface, content and delivery layers assemble into a readable example | Repeating the hero's rings with a different caption |
| Portfolio images | An aperture exposes the actual work while captions stay readable | Decorative cube unrelated to projects |
| A staged process | A path connects the real steps in order | Fake counters |
| A long editorial statement | Phrases settle into a deliberate composition within reserved space | Scrambling essential letters |
| A capability map | A shared token travels between actual disciplines | Continuous random wobble |
| Enquiry | The page's visual object docks beside a clear action | A magnetic button that escapes the pointer |

Use [the section host](../assets/section-motion.mjs) with caller-authored desktop and phone timeline builders. It supplies ScrollTrigger ownership, responsive teardown and an inspectable registry; it does not invent the design. Phone staging is authored separately, not a shrunken desktop pin. CSS supplies complete static content. Motion for React may own presence on separate wrappers when requested.

Run `node scripts/review-motion.mjs <URL> --out <directory>` for actual normal-motion frames at 0/25/50/75/100% on desktop and phone. Review continuous playback too: samples can miss awkward transitions. A property change proves movement, not quality. Inspect reading rhythm, visual continuity, end states, repetition, CTA stability and whether the motion belongs to this subject. Check reduced motion, pause/resume, responsive cleanup and no-JS independently. Never call a static screenshot, recipe count or functional test a motion-quality pass.

If a comparison shares its animation controller, disclose that confound. Do not attribute the builder's shared code to a competitor skill or claim independent superiority. Fix the weakest observed transition and repeat the review.

For selectable content, test the result from the control's actual phone position. A tab whose panel changes below the viewport has failed its feedback job even when the click handler works. Use an adjacent inline disclosure on phones, or explicitly bring the resulting panel into view without moving keyboard focus unexpectedly. Test the first, middle and final option.

Review recurring motifs with the brand names covered: a sculpture may anchor the opening and closing, but services should expose their actual outputs and the process should connect actual steps. Do not mistake twenty different transforms of the same ornament for twenty distinct content experiences. In long briefs, protect a few focal sequences and compress their quieter connective sections.
